# 検査ルールをコードではなく設定ファイルで書く

## 決定

front-matter の検査ルール（許可するフィールド、必須、型、enum、正規表現、一意性、参照、閉路）は Go のコードに書かず、リポジトリ root の `docs-lint.yaml` に宣言する。docs-lint はその設定を解釈するだけで、特定のリポジトリのスキーマを知らない。

## 理由

この linter は複数のリポジトリで使う前提で切り出した。ルールをコードに埋めると、利用側は自前で Go のコードを持つか、docs-lint を fork するかになる。設定で書ければ、利用側は `docs-lint.yaml` と CI からの呼び出しだけを持てばよく、Go のコードを 1 行も持たずに済む。

設定の未知キーは拒否する。`include` を `includes` と書き間違えたときに黙って検査が無効化されると、緑の CI が「検査した」ことを意味しなくなるため。同じ理由で、include に 1 件もマッチしない場合もエラーにする（意図的な場合は `allow_no_files` で明示する）。

## 自分自身への適用

docs-lint 自身のこのディレクトリ（`docs/decisions/`）も `docs-lint.yaml` の対象にしており、CI で `go run ./cmd/docs-lint` を実行して検査する。利用側に課すルールを自分でも運用して、設定の書きやすさと出力の読みやすさを確認する目的。
